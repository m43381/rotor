# 0015. Печатные формы: HTML-шаблоны в песочнице, WeasyPrint, шрифты в образе

## Статус
Принято (2026-09-27, план фазы 6, шаг 6b)

## Контекст

Обязательные формы (open-questions №15):
- график нарядов на месяц;
- суточная ведомость и приказ на дату (№53);
- отчёт по нагрузке (шаг 6c).

Образцов оформления нет. Шаблоны должны заменяться без правки кода (№51), реквизиты — задаваться по подразделениям (№52). Контур изолирован: внешних шрифтов, сервисов и CDN нет (CLAUDE.md, НФТ). Нужны PDF для печати, а также XLSX и DOCX для доработки вручную.

## Варианты

1. **HTML + CSS → PDF (WeasyPrint)**, XLSX и DOCX — кодом.
   - Плюсы: шаблон — обычный HTML, его правит любой, кто знает вёрстку; CSS Paged Media даёт поля, альбомную ориентацию, повтор шапки таблицы и номера листов; лицензия BSD.
   - Минусы: нужны системные библиотеки (pango) — в образе они есть, на машине разработчика с Windows нет.
2. **Шаблоны DOCX (docxtpl) → PDF через LibreOffice.**
   - Плюсы: шаблон правится в Word.
   - Минусы: LibreOffice добавляет в образ сотни мегабайт, конвертация медленная и хрупкая; docxtpl — LGPL.
3. **PDF кодом (ReportLab).**
   - Плюсы: без системных зависимостей.
   - Минусы: шаблон не заменить без программиста; ReportLab — смешанная лицензия (часть функций коммерческая).

## Решение

**Вариант 1.**
- Три встроенные PDF-формы — самодостаточные HTML-шаблоны Jinja2 со стилями внутри, в пакете `documents`. Суперадминистратор загружает свою версию формы:
  - шаблон проверяется отрисовкой на демо-данных, ошибка сообщается с номером строки;
  - версии хранятся в `print_template`, действует последняя активная; «вернуть встроенный» снимает активность;
  - всё пишется в журнал аудита сервиса.
- **Песочница.** Шаблоны выполняются в `SandboxedEnvironment` Jinja2, без загрузчика файлов и с автоэкранированием. Обращение к служебным атрибутам (`__class__`, `__subclasses__` и т. п.) даёт ошибку «шаблон обращается к недоступным данным». У WeasyPrint базовый URL пустой, внешних ресурсов нет.
- **Одна модель данных формы** (`documents.forms`) питает HTML-шаблон, генератор XLSX (openpyxl) и генератор DOCX (python-docx), поэтому по содержанию форматы не расходятся. В XLSX и DOCX меняются только реквизиты.
- **Реквизиты** («УТВЕРЖДАЮ», составитель) хранятся в `document_settings` по подразделениям; при печати действуют реквизиты подразделения или ближайшего вышестоящего. Черновик графика печатается с пометкой «ПРОЕКТ» и без «УТВЕРЖДАЮ» (№58).
- **Шрифты.** Liberation Serif (OFL, метрически совместим с Times New Roman) и DejaVu ставятся пакетами Debian при сборке образа, кэш fontconfig строится там же. Это отступление от плана фазы 6: там были PT Astra. Пакеты дистрибутива проще воспроизводить офлайн (ADR-0007), а метрики Times New Roman привычны для служебных документов.
- **Данные** для форм берутся у `scheduling` от имени оператора (ADR-0014): `GET /schedules/{id}/print` и `GET /rosters/daily`. Звания и полные ФИО `scheduling` получает у `personnel` пачкой.

## Последствия

- PDF-тесты выполняются там, где есть pango: в образе и в CI (устанавливается в workflow). На Windows они пропускаются, остальные тесты форм проверяют HTML, XLSX и DOCX.
- Печать синхронная: график месяца — доли секунды (`docs/plans/phase-6.md`, статус 6b). Фоновая пакетная печать — только если понадобится.
- Изменение формы данных шаблона — изменение контракта для загруженных шаблонов. Доступные переменные описаны на странице шаблонов (`/templates/{form}` → `variables`).
