# DutyFlow — руководство администратора

Этот документ описывает установку и эксплуатацию DutyFlow на сервере изолированной сети. Документ входит в пакет поставки. Все действия выполняет один скрипт `./dutyflow.sh` в каталоге пакета. Команда `./dutyflow.sh` без аргументов выводит список команд.

## Требования к серверу

- Linux x86-64. Эталонная конфигурация: 8 CPU, 16 ГБ ОЗУ, 100 ГБ диска под данные и резервные копии.
- Docker Engine 24+ с плагином compose v2.20+ (проверить: `docker compose version`).
- Утилиты bash, tar, sha256sum. Python и доступ в интернет не нужны.
- Один порт HTTP доступен с рабочих мест: по умолчанию 8088, номер задаётся в `.env` (`GATEWAY_PORT`). Стенд работает только по HTTP (ADR-0021).

## Состав пакета

| Файл | Назначение |
|---|---|
| `images.tar.gz` | образы DutyFlow этой версии, а также PostgreSQL, Redis и Keycloak |
| `docker-compose.yml` | описание стенда; образы только локальные (`pull_policy: never`) |
| `.env.example` | шаблон настроек |
| `dutyflow.sh` | установка, обновление, резервные копии, проверка |
| `nginx/`, `keycloak/`, `postgres/` | конфигурация шлюза, realm Keycloak, скрипты БД |
| `VERSION`, `MANIFEST.sha256` | версия и контрольные суммы файлов пакета |

## Установка

```sh
sudo tar xf dutyflow-1.0.0.tar -C /opt
cd /opt/dutyflow-1.0.0
./dutyflow.sh install        # создаёт .env со случайными паролями и останавливается
```

Откройте `.env` и проверьте настройки:

- `SERVER_HOST` — IP или имя сервера, которое пользователи вводят в браузере, например `10.0.0.5`.
- `GATEWAY_PORT` — внешний порт, по которому заходят пользователи. `PUBLIC_URL` собирается из имени и порта сам; для порта 80 задайте `PUBLIC_URL=http://${SERVER_HOST}`, без порта.
- `BACKUP_DIR` — каталог резервных копий. Лучше указать абсолютный путь вне каталога пакета, например `/var/backups/dutyflow`: тогда копии не зависят от версии пакета.

Затем повторите установку:

```sh
./dutyflow.sh install        # проверка пакета, загрузка образов, запуск
./dutyflow.sh doctor         # через 1–2 минуты, когда Keycloak закончит запуск
```

**Первый вход.** Логин `admin`, пароль берётся из `DUTYFLOW_ADMIN_PASSWORD` в `.env`. Смените его в разделе «Сменить пароль». Операторов администратор создаёт в разделе «Операторы». Самостоятельной регистрации нет.

`.env` содержит все пароли стенда. Храните его как секрет: права 600, в копиях — отдельно от общего доступа.

## Установка из репозитория (GitHub)

Второй способ установки, без пакета поставки. Образы собираются прямо на сервере, поэтому при сборке серверу нужен доступ к GitHub, Docker Hub, PyPI и npm. После сборки стенд работает без интернета. Нужны Docker Engine 24+ с compose v2.20+, git и bash (на Windows подойдёт Git Bash).

```sh
git clone https://github.com/m43381/rotor.git dutyflow
cd dutyflow/deploy
./dutyflow.sh init             # создаёт .env со случайными паролями, больше ничего не делает
```

В `.env` поправьте строки в начале файла:

| Переменная | Что указать |
|---|---|
| `SERVER_HOST` | IP или DNS-имя сервера, которое пользователи вводят в браузере, например `192.168.1.50` |
| `GATEWAY_PORT` | внешний порт, по которому заходят пользователи (по умолчанию 8088) |
| `BACKUP_DIR` | каталог резервных копий; лучше абсолютный путь вне репозитория |

`PUBLIC_URL` собирается из этих строк автоматически, его менять не нужно. Исключение — стандартный порт 80: тогда задайте `PUBLIC_URL=http://${SERVER_HOST}`, без порта.

Запуск (из каталога `deploy/`):

```sh
docker compose up -d --build   # первая сборка — 5–15 минут
./dutyflow.sh doctor           # через 1–2 минуты, когда Keycloak закончит запуск
```

Стенд открывается по адресу `http://<SERVER_HOST>:<GATEWAY_PORT>`, логин `admin`, пароль — `DUTYFLOW_ADMIN_PASSWORD` из `.env`. Если сервер с рабочих мест не открывается, проверьте брандмауэр сервера: порт `GATEWAY_PORT` должен быть разрешён для входящих подключений.

**Смена внешнего порта** (например, если порт уже занят): поменяйте `GATEWAY_PORT` в `.env` и выполните `docker compose up -d`. Шлюз, адрес Keycloak, адреса возврата после входа и проверка токенов подстроятся сами.

**Смена адреса сервера:** поменяйте `SERVER_HOST` и выполните `docker compose up -d`.

**Обновление** до новой версии из репозитория:

```sh
./dutyflow.sh backup
git pull
./dutyflow.sh init             # допишет в .env новые переменные, пароли не меняются
docker compose up -d --build   # миграции БД применяются при старте сервисов
```

Имя compose-проекта — `dutyflow`, поэтому на одной машине работает одна копия стенда. Данные хранятся в томах `dutyflow_pgdata` и `dutyflow_redisdata`. Команда `docker compose down -v` удаляет их безвозвратно.

## Демонстрационные данные

На запущенном стенде (после первого входа можно сразу):

```sh
./dutyflow.sh demo             # около 2 минут
```

Загружается учебная академия:
- 9 факультетов, у каждого кафедры N1, N2, N5 и курсы N1–N5; на курсах по 4–6 учебных групп; кафедра 102 при академии;
- около 5 200 человек: начальство академии, факультетов и курсов (прямо в этих подразделениях), преподаватели кафедр, курсанты в группах; на 9-м факультете — слушатели;
- справочники: звания, должности, характеристики (курс, пол, водительское удостоверение, физподготовка, допуск к оружию), категория «Гражданский персонал»;
- наряды академии (дежурный по академии, караул, КПП, столовая), факультетов, курсов и локальные наряды кафедр;
- допуски примерно у 70 % подходящих людей, освобождения примерно у 6 %;
- около 90 учётных записей с паролем `demo-password-1`: `fak6_admin`, `fak6_operator` (факультеты), `kurs61` (курсы), `kaf61`, `kaf102` (кафедры), `nablyudatel` (наблюдатель по всей академии).

Данные идут через API от имени `admin`, как ручной ввод, и попадают в журнал изменений. Повторный запуск ничего не дублирует, а уже существующие записи не меняет. Описание данных — в `demo/demo.py`.

Для рабочей эксплуатации демо-данные не нужны: на чистом стенде есть только корневое подразделение и `admin`.

## Работа по HTTP

Стенд работает по обычному HTTP (ADR-0021): сертификаты не нужны, на рабочие места ничего устанавливать не надо. Пароли и токены при этом передаются по сети открытым текстом, поэтому стенд должен быть доступен только из доверенной локальной сети.

Вход работает и по IP-адресу. Браузер даёт криптографический API (`crypto.subtle`) только на HTTPS и `localhost`, поэтому для входа по `http://<IP>` интерфейс использует встроенную реализацию SHA-256.

## Ежедневная работа

| Команда | Что делает |
|---|---|
| `./dutyflow.sh status` | состояние контейнеров |
| `./dutyflow.sh doctor` | полная проверка: контейнеры, сервисы, Keycloak, очереди событий, свежесть копий; код выхода 1 при проблемах |
| `./dutyflow.sh logs [сервис]` | журналы контейнеров (например, `logs scheduling`); хранится до 5 файлов по 20 МБ на контейнер |
| `./dutyflow.sh down` / `up` | остановка / запуск |

Стенд запускается автоматически вместе с Docker после перезагрузки сервера (`restart: unless-stopped`).

## Резервные копии

`./dutyflow.sh backup` создаёт каталог `BACKUP_DIR/<ГГГГММДД-ЧЧММСС>/`:

- `*.dump` — все БД, включая Keycloak (учётные записи операторов);
- `SHA256SUMS` — контрольные суммы;
- `config/` — копия `.env`, без которой копию не поднять на другом сервере.

Копии старше `BACKUP_KEEP_DAYS` дней (по умолчанию 14) удаляются при следующем запуске. Копия делается без остановки работы.

**Ежедневный запуск** (cron пользователя root, в 02:00):

```cron
0 2 * * * /opt/dutyflow-1.0.0/dutyflow.sh backup >> /var/log/dutyflow-backup.log 2>&1
```

При обновлении версии поправьте путь в этой строке.

Копия содержит персональные данные и пароли. Шифрование обеспечивается средствами хоста или носителя: зашифрованный раздел, защищённое хранилище. Храните копии не только на этом сервере: регулярно переносите их на отдельный носитель.

## Восстановление

**На том же сервере:**

```sh
./dutyflow.sh restore /var/backups/dutyflow/20261001-020000
```

Скрипт спрашивает подтверждение. Затем он останавливает сервисы, проверяет контрольные суммы, пересоздаёт все БД из копии, очищает очереди событий и запускает стенд. Всё, что было изменено после момента копии, теряется.

**На новом сервере:**

1. Распакуйте пакет той же версии, что и копия.
2. Скопируйте `config/.env` из копии в каталог пакета. Если у сервера новый адрес, поправьте `SERVER_HOST`.
3. Выполните `./dutyflow.sh install`, затем `./dutyflow.sh restore <каталог копии>`.

## Обновление

Новая версия распаковывается рядом со старой. Старый каталог остаётся и нужен для отката.

```sh
sudo tar xf dutyflow-1.1.0.tar -C /opt
cd /opt/dutyflow-1.1.0
./dutyflow.sh update /opt/dutyflow-1.0.0
```

`update` выполняет следующие шаги:

1. переносит `.env` из старого каталога;
2. делает резервную копию, пока работает старая версия;
3. загружает образы новой версии;
4. дописывает в `.env` новые настройки, не меняя существующие пароли;
5. запускает стенд. Миграции БД применяются автоматически при старте сервисов.

После обновления выполните `./dutyflow.sh doctor` и исправьте путь в строке cron.

## Откат

Новая версия могла изменить схему БД, поэтому для отката нужна копия, сделанная перед обновлением. Её имя `update` печатает в начале работы.

```sh
cd /opt/dutyflow-1.0.0
./dutyflow.sh restore /var/backups/dutyflow/<копия перед обновлением>
```

Команда восстанавливает данные на момент копии и запускает старую версию: образы старой версии остаются загруженными. Изменения, внесённые после обновления, теряются.

## Типичные проблемы

| Признак | Причина и действие |
|---|---|
| Страница грузится, но вход не открывается или обрывается | Адрес в браузере не совпадает с `SERVER_HOST`: вход перенаправляет на `PUBLIC_URL`. Например, открыт `http://127.0.0.1:8088`, а в `.env` — `localhost`. Укажите в `SERVER_HOST` ровно то, что вводят в браузере, и выполните `docker compose up -d`. |
| Страница не открывается с рабочих мест | Порт `GATEWAY_PORT` закрыт брандмауэром сервера или занят другим процессом (`docker compose ps` покажет ошибку шлюза). Откройте порт или смените его в `.env`. |
| Браузер сам переходит на `https://` | Раньше по этому адресу работал HTTPS, и браузер запомнил HSTS. Очистите HSTS для адреса (Chrome/Edge: `chrome://net-internals/#hsts` → Delete domain security policies) или откройте адрес в окне инкогнито. |
| После входа ошибка Keycloak «Invalid redirect uri» | `PUBLIC_URL` не совпадает с адресом в браузере. Исправьте `.env` и выполните `./dutyflow.sh up`: адреса возврата обновятся автоматически. |
| `doctor`: сервис не работает | Смотрите `./dutyflow.sh logs <сервис>`. Частая причина — нехватка памяти; проверьте `free -h`. |
| `doctor`: отставание очереди | Консьюмер не успевает или остановлен; смотрите `logs <сервис>-consumer`. Отставание уменьшается само после устранения причины. |
| `doctor`: `dlq:*` не пуст | Событие не удалось обработать 5 раз, и оно отложено. Просмотр: `docker compose exec redis redis-cli XRANGE dlq:events:<поток> - + COUNT 10`. После исправления причины (обычно по журналу консьюмера) обратитесь к разработчику: повторная обработка выполняется вручную. |
| Долгие распределения завершаются ошибкой памяти | Увеличьте `ALLOCATION_WORKER_MEMORY` в `.env` (по умолчанию 4g) и выполните `./dutyflow.sh up`. |
| Администратор забыл пароль | Консоль Keycloak `PUBLIC_URL/auth/admin/`, логин `KEYCLOAK_ADMIN`, пароль `KEYCLOAK_ADMIN_PASSWORD` из `.env` → realm `dutyflow` → Users → `admin` → Credentials → Reset password (Temporary). |
