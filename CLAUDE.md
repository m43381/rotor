# DutyFlow 2 — контекст проекта для Claude Code

> Положи этот файл в корень НОВОГО репозитория. Claude Code читает его в начале каждой сессии.

## Что это

Программный комплекс автоматизированного распределения ресурсов подразделений (нарядов и личного состава) в условиях изолированных сетевых инфраструктур. Дипломный проект. Работает только в локальной сети, без доступа в интернет.

Это новый продукт, написанный с нуля. Старая версия (Django-монолит) лежит в `../duty_flow/duty_flow` и служит **только справочником** по доменной логике и источником данных для миграции. Код оттуда не копировать; её архитектурные решения не считаются обязательными.

## Предметная область (глоссарий)

- **Подразделение (Unit)**: узел дерева, родитель → дети, произвольная глубина. У каждого есть **тип** с уровнем иерархии (академия → факультет → кафедра → …).
- **Личный состав (Person)**: люди внутри подразделения. Это **данные, а не пользователи**: у них нет учётных записей. Атрибуты: ФИО, звание (упорядоченный справочник), подразделение, должность, расширяемые характеристики, допуски, освобождения.
- **Допуск (Clearance)**: право человека заступать на определённый тип наряда или на роль в нём. Может иметь срок действия.
- **Освобождение (Exemption)**: период, когда человек недоступен (болезнь, отпуск, командировка, прочее).
- **Тип наряда (DutyType)**: кто создал (подразделение), сколько человек требуется, закреплённое подразделение (опционально). В новой версии у наряда есть **состав по ролям** (например, дежурный ×1 и дневальный ×2), и у каждой роли свои требования.
- **График (Schedule)**: подразделение × месяц, статусы draft → published → archived.
- **План дня (DayPlan)**: ячейка «дата начала × тип наряда × роль → подразделение-исполнитель» (ADR-0008, ADR-0009). Вышестоящее подразделение **делегирует** ячейки дочерним («входящий наряд» в статусе pending → accepted), а те могут делегировать дальше по цепочке.
- **Назначение (Assignment)**: человек, поставленный в конкретную ячейку.
- **Оператор**: единственный вид пользователя системы. Привязан к подразделению и видит данные в пределах своего **scope** (своё подразделение, прямые дети, всё поддерево, всё). Самостоятельной регистрации нет, пользователей создаёт администратор.

## Нефункциональные требования

- До 5 000 учётных записей операторов (реально до 1 000, остальное — запас). Личного состава реально больше 5 000 человек, закладываемся на 20–50 тыс.
- Полная изоляция: никаких CDN, внешних шрифтов, телеметрии и обращений в интернет во время работы. Все ассеты собираются в образ.
- Распределение на месяц для крупного подразделения должно укладываться в секунды. Цель задаётся в бенчмарках.
- Каждое изменение данных попадает в журнал аудита: кто, что, когда, было → стало.
- Работа запускается через `docker compose` (в перспективе возможен k8s, но сейчас он не нужен).

## Стек

- Backend: Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2.0 (async) + asyncpg, Alembic (миграции в каждом сервисе свои), uv, ruff, mypy, pytest.
- Алгоритмы: numpy (векторные фильтры и скоринг), scipy (`linear_sum_assignment`), Google OR-Tools (CP-SAT, min-cost flow).
- Frontend: Vue 3 + TypeScript + Vite, Pinia, Vue Router, PrimeVue **4.x, MIT** (не 5.x: там коммерческая лицензия, см. ADR-0012), Apache ECharts (vue-echarts). API-клиент генерируется из OpenAPI.
- Хранилище: PostgreSQL 16. Одна инсталляция, **отдельная БД на каждый сервис**, иерархия хранится через `ltree`.
- Очереди и события: Redis (Streams для доменных событий, arq для фоновых задач) + transactional outbox.
- Auth: Keycloak (OIDC, JWT), подтверждён в ADR-0002. Регистрация отключена.
- Шлюз: nginx (раздача SPA, reverse proxy, TLS на внутреннем CA).

## Сервисы (целевая схема; не дробить сильнее без ADR)

| Сервис | Ответственность |
|---|---|
| `gateway` | nginx: SPA, маршрутизация `/api/<service>/`, TLS |
| `auth` | Keycloak + тонкий `auth-admin` (FastAPI) для создания операторов из UI |
| `org` | подразделения, типы, дерево (ltree), звания, справочники, производственный календарь |
| `personnel` | личный состав, характеристики, допуски, освобождения |
| `scheduling` | графики, планы дней, workflow делегирования, ручные назначения, закрепления (pin) |
| `allocation` | движок распределения: чистые функции «снимок → решение» и воркер для долгих задач |
| `analytics` | read-model по событиям, агрегаты, метрики справедливости, API для дашбордов |
| `documents` | импорт (xlsx/csv с предпросмотром и отчётом об ошибках), печать (PDF через WeasyPrint, DOCX, XLSX) |

Общий код лежит в `libs/common`: проверка JWT, контекст оператора, политика доступа (роль × ресурс × действие × scope), outbox, логирование, пагинация, ошибки.

## Структура репозитория

```
services/<name>/        # app/, migrations/, tests/, Dockerfile, pyproject.toml
libs/common/
frontend/
deploy/                 # docker-compose*.yml, nginx, keycloak realm export, .env.example
docs/adr/               # архитектурные решения (NNNN-title.md)
docs/                   # анализ legacy, модель данных, алгоритм, бенчмарки
tools/                  # генератор синтетических данных, миграция из legacy, бенчмарки
```

## Правила работы

1. **Сначала план, потом код.** Если задача затрагивает больше одного сервиса или меняет модель данных, сначала предложи план или ADR и дождись подтверждения.
2. Если требования неоднозначны, **задавай вопросы**, а не угадывай. Список открытых вопросов веди в `docs/open-questions.md`.
3. Каждое значимое решение оформляй как ADR: контекст, варианты, решение, последствия. ADR потом войдут в пояснительную записку.
4. Никаких N+1: данные для расчёта загружаются пачкой, вычисления идут в памяти.
5. Сервисы не ходят в чужие БД. Взаимодействие идёт только через HTTP API (внутренние batch-эндпоинты) или события.
6. Движок распределения детерминирован (одинаковый вход и seed дают одинаковый выход), не зависит от БД и покрыт тестами и бенчмарками.
7. Секреты не коммитятся. В репозитории лежит только `.env.example`.
8. Логику старой системы брать можно, код — нет. Если меняешь бизнес-правило из legacy, явно это отметь.
9. В `../duty_flow/duty_flow` **не читай целиком** `full_export.txt`, `project_snapshot_full.txt` и `data.json`: это дампы по 300–600 КБ, дублирующие код. Если нужны данные, используй grep.
10. Язык интерфейса и документации — русский. Код и идентификаторы пиши на английском.

## Команды

Команды запускаются через [`just`](https://github.com/casey/just) (`justfile` в корне), `make` не используется. Полный список: `just --list`.

| Команда | Что делает |
|---|---|
| `just install` | Зависимости Python (uv workspace) и фронтенда |
| `just up` / `just down` / `just reset` | Поднять стенд, остановить, остановить с удалением данных. Стенд: https://localhost:8443 (сертификат внутреннего УЦ `deploy/certs/ca.crt`; 8088 перенаправляет на HTTPS) |
| `just seed` | Демо-дерево подразделений, демо-учётки (`faculty_admin`, `course_operator`, `faculty_viewer`, `department_operator`, пароль `demo-password-1`), ~900 человек личного состава (курсанты и постоянный состав: управления факультетов, кафедры), наряды академии, факультетов и курсов с ролями и требованиями, допуски; идемпотентен |
| `just lint` | ruff, ruff format, mypy strict, eslint, vue-tsc, проверка лицензий фронтенда |
| `just test` | pytest (интеграционные тесты на Postgres через testcontainers, нужен Docker) и vitest |
| `just e2e` | Playwright против поднятого стенда, системный Edge/Chrome |
| `just gen-api` | Типы API фронтенда из OpenAPI сервисов |
| `just screenshots` | Скриншоты UI для пояснительной записки |
| `just backup` / `just restore <каталог>` | Резервная копия всех БД (включая Keycloak) и настроек в `deploy/backups/` / восстановление из неё |
| `just doctor` | Проверка стенда: контейнеры, `/health`, очереди событий, сертификат, свежесть копий |
| `just certs` | Перевыпуск сертификата HTTPS на имена из `TLS_HOSTS` (корневой сохраняется) |
| `just load up\|populate\|run\|down` | Нагрузочный прогон (№62) на отдельном стенде `dutyflow-load` (:9443): 50 тыс. человек, 5 000 операторов, 300 активных → `docs/benchmarks/load.md`; наполнение — около часа, dev-стенд на это время лучше остановить |
| `just bundle <версия>` | Пакет поставки для изолированной сети → `dist/` (установка и эксплуатация: `deploy/README.md`, `deploy/dutyflow.sh`) |

Операторов создают администраторы в разделе «Операторы» (сервис `auth-admin`, ADR-0016); Keycloak настраивает одноразовый контейнер `keycloak-init` при каждом `just up`. Пароль администратора `admin` лежит в `deploy/.env` (`DUTYFLOW_ADMIN_PASSWORD`). Файл создаётся `just env` со случайными секретами. Бенчмарки: `just bench` (иерархия), `just bench-people` (снимок личного состава) и `just bench-schedule` (таблица месяца и снимок задачи), `just bench-allocation` (движок распределения), `just bench-import` (импорт до 20 000 строк) → `docs/benchmarks/`. Read-model аналитики перестраивается из фактов scheduling командой `just analytics-rebuild` (стенд поднят). Экспериментальный стенд фазы 5 (legacy против методов движка, 1k–50k, затухание, пороги auto): `just experiment` → `docs/experiments.md` (десятки минут; `just experiment --report` — только отчёт по готовым данным).
